Q22. Assess the Concept of Serializability and Its Importance in Maintaining Database Consistency.

1. Serializability

Serializability is a concept in DBMS that ensures multiple transactions executing at the same time produce the same result as executing them one after another.

It helps maintain database consistency by ensuring correct results during concurrent execution.

2. Types of Schedules

a) Serial Schedule

  • Transactions execute one after another.
  • One transaction completes before the next transaction begins.
  • There is no overlapping of operations.

b) Non-Serial Schedule

  • Operations of multiple transactions are mixed together.
  • Transactions can execute at the same time.
  • A non-serial schedule is serializable if it is equivalent to a serial schedule.

Operations of T1 and T2 are interleaved.

3. Types of Serializability

a) Conflict Serializability

A schedule is conflict serializable if it can be rearranged into a serial schedule without changing the order of conflicting operations.

A precedence graph is used to check it.

  • A graph without a cycle is conflict serializable.
  • A graph with a cycle is not conflict serializable.

A cycle exists between T1 and T2.

b) View Serializability

A schedule is view serializable if transactions read from the same sources and have the same final writes as a serial schedule.

4. Importance of Serializability in Database Consistency

  1. Maintains Consistency: Ensures concurrent transactions produce results equivalent to serial execution.
  2. Prevents Incorrect Results: Helps avoid problems such as lost updates and incorrect calculations.
  3. Supports Concurrent Execution: Allows multiple transactions to execute together while maintaining correctness.
  4. Maintains Data Integrity: Helps preserve database rules when transactions are executed concurrently.

Example: If two transactions update the same bank account, serializability ensures the final balance is the same as if the transactions were executed one after another.
