Q29. Discuss the ER Model. Construct an ER Diagram for a University Management System, Clearly Showing Entities, Attributes, and Relationships.

1. Introduction

The Entity-Relationship (ER) Model is a database model used to represent entities, their attributes, and the relationships between them.

It was introduced by Peter Chen in 1976 and is used to design the structure of a database.

2. ER Diagram of University Management System

3. Main Components of the ER Model

1. Entity

An entity is a real-world object about which data is stored.

  • STUDENT: Represents students studying at the university.
  • COURSE: Represents courses offered by the university.
  • TEACHER: Represents teachers who teach courses.

In an ER diagram, an entity is represented by a rectangle.

2. Attributes

An attribute is a property that describes an entity.

  • STUDENT: Student_ID, Name, Email.
  • COURSE: Course_ID, Course_Name, Credits.
  • TEACHER: Teacher_ID, Name.

In an ER diagram, an attribute is represented by an oval.

3. Primary Keys

A primary key is an attribute that uniquely identifies each record of an entity.

  • Student_ID: Primary Key of STUDENT.
  • Course_ID: Primary Key of COURSE.
  • Teacher_ID: Primary Key of TEACHER.

In an ER diagram, a primary key is shown by underlining the attribute name.

4. Relationships

A relationship shows how two entities are connected.

ENROLLS (STUDENT – COURSE)

  • A student can enroll in many courses.
  • A course can have many students.
  • Cardinality: Many-to-Many (M:N).

TEACHES (TEACHER – COURSE)

  • A teacher can teach many courses.
  • Each course is taught by one teacher.
  • Cardinality: One-to-Many (1:N).

In an ER diagram, a relationship is represented by a diamond.
