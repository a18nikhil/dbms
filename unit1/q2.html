Q2. Design an ER Diagram for a Library Management System, identifying entities, attributes, keys, and relationships.

An ER (Entity-Relationship) Diagram is a graphical representation of the structure of a database. It shows entities, their attributes, keys, and relationships between entities.

ER Diagram of Library Management System:

1. Entity

An entity is a real-world object about which data is stored in a database.

In the Library Management System, the main entities are:

  • BOOK: Represents books in the library.
  • MEMBER: Represents people who borrow books.
  • PUBLISHER: Represents publishers of books.

In an ER diagram, an entity is represented by a rectangle.

2. Attributes

An attribute is a property or characteristic that describes an entity.

  • BOOK: Book_ID, Title, Author, Price
  • MEMBER: Member_ID, Name, Phone, Address
  • PUBLISHER: Pub_ID, Name, Address

In an ER diagram, an attribute is represented by an oval.

3. Keys

A key is an attribute that uniquely identifies each entity record.

  • Book_ID → Primary Key of BOOK
  • Member_ID → Primary Key of MEMBER
  • Pub_ID → Primary Key of PUBLISHER

In an ER diagram, a key is shown by underlining the attribute name.

4. Relationships

A relationship shows how two or more entities are connected.

BORROWS

  • Connects MEMBER and BOOK.
  • A member can borrow many books, and a book can be borrowed by many members over time.
  • Cardinality: Many-to-Many (M:N)
  • Relationship attributes: Issue_Date, Return_Date

PUBLISHED_BY

  • Connects BOOK and PUBLISHER.
  • One publisher can publish many books, while each book is published by one publisher.
  • Cardinality: Many-to-One (N:1)

In an ER diagram, a relationship is represented by a diamond.
