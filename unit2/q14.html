Q14. Discuss the Integrity Rules (Entity Integrity and Referential Integrity) in the Relational Model.

Integrity Rules are rules used in a relational database to keep data accurate, correct, and consistent.

The two main integrity rules are Entity Integrity and Referential Integrity.

1. Entity Integrity

Entity Integrity states that a Primary Key cannot contain NULL values because it is used to uniquely identify each record in a table.

Rules:

  • Primary Key values must be unique.
  • A Primary Key cannot contain NULL values.

Example: STUDENT Table

Student_ID (PK) Name
101 Rahul
102 Priya
103 Amit

Here, Student_ID is the Primary Key. Each student must have a unique and non-NULL Student_ID.

2. Referential Integrity

Referential Integrity states that a Foreign Key value must match an existing Primary Key value in the referenced table or be NULL if allowed.

It ensures that relationships between tables remain valid.

Example: STUDENT and ENROLLMENT Tables

STUDENT

Student_ID (PK) Name
101 Rahul
102 Priya

ENROLLMENT

Enroll_ID Student_ID (FK) Course
1 101 DBMS
2 102 Python

Here, Student_ID in ENROLLMENT is a Foreign Key referring to Student_ID in STUDENT.

  • Student_ID 101 and 102 are valid because they exist in STUDENT.
  • Student_ID 105 cannot be inserted into ENROLLMENT because it does not exist in the STUDENT table.

3. Difference Between Entity Integrity and Referential Integrity

Entity Integrity Referential Integrity
Applies to Primary Keys. Applies to Foreign Keys.
Primary Key cannot be NULL. Foreign Key must match a referenced key or be NULL if allowed.
Ensures each record is uniquely identified. Ensures valid relationships between tables.
