Q16. What is BCNF (Boyce-Codd Normal Form)? Explain How It Differs from 3NF with an Example.

BCNF (Boyce-Codd Normal Form) is a higher level of database normalization. It is a stricter form of Third Normal Form (3NF).

A table is in BCNF when every determinant is a Super Key.

  • Determinant: A column or combination of columns that determines the value of another column.
  • Super Key: A column or group of columns that uniquely identifies each row.

1. Difference Between 3NF and BCNF

3NF BCNF
Removes transitive dependency of non-key columns. Every determinant must be a Super Key.
Allows some determinants that are not Super Keys. Does not allow determinants that are not Super Keys.
Less strict than BCNF. More strict than 3NF.
A table in 3NF may not be in BCNF. Every BCNF table is also in 3NF.

2. Example of BCNF

Consider the following table:

STUDENT_COURSE

Student_ID Course Instructor
101 DBMS Rahul
102 DBMS Rahul
101 Python Priya
103 Python Priya

Assume that:

  • A student can study multiple courses.
  • A course can have multiple instructors.
  • Each instructor teaches only one course.
  • Each student has only one instructor for each course.

Here:

  • Candidate Key 1: (Student_ID, Course)
  • Candidate Key 2: (Student_ID, Instructor)
  • Functional Dependency: Instructor → Course means each instructor teaches only one course.

The table is in 3NF because Course is part of a Candidate Key. However, it is not in BCNF because Instructor determines Course, but Instructor is not a Super Key.

3. Converting the Table into BCNF

To convert the table into BCNF, divide it into two tables.

INSTRUCTOR_COURSE

Instructor Course
Rahul DBMS
Priya Python

STUDENT_INSTRUCTOR

Student_ID Instructor
101 Rahul
102 Rahul
101 Priya
103 Priya

Now both tables are in BCNF because every determinant is a Super Key.
