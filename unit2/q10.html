Q10. Explain the Logical View of Data and the Concept of Keys in a Relational Database with Examples.

1. Logical View of Data

The logical view of data describes how data is organized in a database as tables, rows, and columns, without showing how the data is physically stored on disk.

For example, in a college application, users can see student IDs, names, marks, and other required information. They do not need to know where or how these records are physically stored.

2. Concept of Keys in a Relational Database

A key is an attribute or a set of attributes used to uniquely identify a record in a relational table and to establish relationships between tables.

Consider the following STUDENT table:

  1. Super Key
    A Super Key is an attribute or combination of attributes that can uniquely identify a record in a table.
    Example: Student_ID can uniquely identify a student. A combination such as Student_ID + Name can also uniquely identify a student. Therefore, both are Super Keys.
  2. Candidate Key
    A Candidate Key is a minimal Super Key, meaning it uniquely identifies a record without any unnecessary attribute.
    Example: If both Student_ID and Email are unique, then Student_ID and Email can be Candidate Keys.
  3. Primary Key
    A Primary Key is the Candidate Key selected as the main identifier of records in a table. It cannot contain NULL values.
    Example: Student_ID can be selected as the Primary Key of the STUDENT table.
  4. Alternate Key
    An Alternate Key is a Candidate Key that is not selected as the Primary Key.
    Example: If Student_ID is selected as the Primary Key and Email is another Candidate Key, then Email becomes the Alternate Key.
  5. Foreign Key
    A Foreign Key is an attribute in one table that refers to the Primary Key of another table. It is used to establish a relationship between tables.

Here, Student_ID in the ENROLLMENT table refers to Student_ID in the STUDENT table.

  1. Composite Key
    A Composite Key is a key consisting of two or more attributes that together uniquely identify a record.

Here, Student_ID alone is not unique and Course_ID alone is not unique. Together, Student_ID and Course_ID uniquely identify an enrollment record. Therefore, they form a Composite Key.
